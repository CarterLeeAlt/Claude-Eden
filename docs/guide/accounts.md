## 先区分三类账户

| 账户或登录 | 用途与归属 |
| --- | --- |
| Claude Eden 账户 | 解锁当前主机的 Claude Eden 工作台。 |
| Claude Code 账号 | 授权环境内终端使用 Claude 订阅，由侧栏“Claude 账号管理”管理与调度。 |
| 网页与 Claude Desktop 登录 | 各自保存登录状态，不会自动加入 Claude Code 调度。 |

点击侧栏“Claude 账号管理”查看账号列表；登录和查询额度前，先启动环境并等待工具就绪。账号功能以所用构建为准；没有该面板时先核对版本。

官方客户端启动时会筛除管理用环境变量，状态栏、登录回调和手机渠道只接收运行所需的信息。账户、凭据、历史和项目保留原位；配置和辅助程序通过临时引用访问。客户端仍拥有正常的终端和项目访问能力，这些处理无法保证供应商不能识别运行环境。

## 将已有登录加入调度

在工作台普通终端运行 `claude auth login`。如果显示 Claude 官方授权链接，点击后在 Workbench 浏览器临时标签继续。完成后回到原终端确认登录结果。

登录成功后，账号面板显示默认终端检测到的邮箱。核对后点“加入调度”。它只读取客机环境里的登录，不读取主机终端上的账号。

如果普通终端原先是 A，后来登录成 B，Claude Eden 停止将默认目录分配给 A，B 需要单独加入。长期共存时保留一份默认登录，另一个通过独立登录添加。

## 添加另一个订阅

1. 在侧栏“Claude 账号管理”点“登录新账号”。
2. 按打开的登录终端和临时授权浏览器提示完成官方登录。每个独立登录使用自己的配置目录。
3. 成功后账号按邮箱登记，可编辑备注，检查“参与自动分配”是否开启。
4. 点击项目旁的终端图标，新建 Claude 终端，查看标签所显示的分配账号。

取消登录不会增加可调度账号。同一订阅不会重复参与调度。独立账号需要重新登录时，先关闭仍使用它的终端，再按面板提示处理。

通过“登录新账号”再次授权已有独立账号时，Claude Eden 按邮箱和组织匹配原账号。Linux 环境中，原目录缺少文件凭据且账号没有运行中的终端、手机任务或登录操作时，可以用本次授权恢复登录；账号目录、会话、备注和参与设置保留。恢复后由官方 CLI 确认身份。

Windows 环境、已有凭据或恢复检查失败时，等待手机任务结束并关闭使用原账号的终端，再从原账号卡片点击“打开登录终端”或“重新登录”。检查失败保留原凭据；面板确认身份后才报告恢复成功。

## 自动分配什么时候发生

自动分配发生在新建 Claude 终端时。在“调度设置”中选择：

- **均衡分配**：考虑正在使用的终端数量和已知剩余额度，条件相近时轮转，并兼顾同一项目近期使用的账号。
- **按列表顺序优先**：优先使用排在前面的可用账号，相关额度已耗尽、登录失效或暂停分配时使用后面的账号。通过“上移”调整顺序。

关闭某个账号的“参与自动分配”，只影响以后新建的终端，正在使用该账号的任务可以继续。改变调度模式不改变已有会话的账号绑定。

## 共享技能、指令和记忆

登录凭据各自独立，Claude Eden 会话列表统一展示历史。项目文件、项目指令与技能共用；用户级本地技能、指令、规则和代理定义使用环境内的共享资料，同一项目的自动记忆使用同一位置。更换账号后仍可使用这些资料，主机个人配置不会自动导入。

从 Claude.ai 账号或组织下载的技能仍属于原账号；身份、凭据、远程设置和 MCP 授权不自动合并。资料同名且内容不同时，Claude Eden 保留原文件并提示核对。

## 在同一会话中换账号

先在账号卡片中填写“接续分组”，将允许接收同一份会话历史的账号设为同一组。未分组的账号不进行跨账号接续。工作资料与个人资料不应随意混入同一组；分组控制自动交接的目标，不构成文件系统安全隔离。

电脑终端上方和手机会话中的账号按钮显示当前绑定。展开后可以选择：

- **每次询问**：由用户选择目标账号，勾选允许交接历史，再执行“切换并恢复历史”。
- **额度耗尽后自动接续**：官方 CLI 报告限流且额度读数确认窗口耗尽时，尝试在同组可用账号间接续。
- **始终等待原账号**：自动接续保持关闭，仍可手动发起一次明确确认的切换。

账号设置中的授权默认只影响新会话；会话内可单独修改。接续保留同一个 Claude Eden 会话入口，目标账号启动新的官方 CLI 并恢复历史。手动切换默认只恢复历史；需要执行时勾选“恢复后继续未完成的任务”。跨账号的服务端提示缓存可能重建，第一轮可能更慢。

交接前必须停止原执行者。执行中的工具、未处理消息、工具审批、后台任务或结果不明的工具会阻止切换。失败后可重试，准备阶段可取消并保留原账号。Claude Eden 不为恢复重放旧消息或已完成工具，但模型后续仍可能再次调用工具，需要检查结果。

这套能力运行客机中的原版 Claude Code。代码接入 Linux 和 Windows 客机路径，需匹配的环境组件；Windows 还需登录并解锁绑定的客机桌面。

当前改名构建仍需验证真实双订阅兼容性、客机完整登录与交接流程。CLI 版本或组织策略不支持 Channels 时，手机接续能力会受限。旧额度、服务过载或未知错误不会被当作已确认的额度耗尽。

## 查看五小时和七天额度

打开面板会向环境内的官方 Claude Code 查询五小时、七天用量与重置时间。卡片的“检查状态”可以立即刷新，无需先发一条模型消息。

某个额度窗口没有返回读数时，界面会说明结果，并保留该窗口上次的百分比和读取时间。旧读数不能视为实时可用额度，也不能代表服务一定接受下一条请求。

## 无账号可分配时

按以下顺序检查：账号是否成功登录、是否开启参与分配、是否已达到已知额度、预计重置时间是否已到。先点“检查状态”，身份失效时按提示重新登录。

普通终端切换过账号时，检查新身份是否单独加入调度。官方授权或请求失败，继续查[Claude 登录与账号异常](troubleshooting.md#claude-登录与账号异常)。
