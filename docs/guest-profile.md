# 客机创建配置与设备检测

在首次设置的“系统与存储 → 客机创建配置”中，选择默认、随机或手动配置。选项仅用于新建本地 Debian 13 环境。

## 默认与可选值

| 项目 | 默认行为 | 可选配置 |
| --- | --- | --- |
| 工作账户 | `developer`，UID 1000，主目录 `/home/developer` | 独立账户名与 `/home/` 下的单层目录 |
| 浏览器账户 | `browser`，独立普通账户，主目录 `/home/browser` | 与工作账户不同的名称、主目录 |
| 主机名 | 按[机器身份规则](guest-identity.md)随机生成 | 1–15 位 ASCII 字母、数字或连字符 |
| 虚拟显示 | 2880 × 1800 | 宽 800–3840，高 600–2160 |
| 浏览器初始窗口 | 1440 × 900 | 不超过虚拟显示的宽高；工作台连接后仍按实际视口调整 |
| 音频 | `workbench_output`，描述 `Workbench` | 随机公开型号标签或手动名称、描述 |
| 内置控制扩展 | `Workbench browser panes`，路径 `/usr/local/lib/workbench-split` | 手动名称；随机和手动配置使用保存的独立扩展路径 |
| 图形渲染 | 自动使用客机可用设备 | ANGLE OpenGL、Vulkan 或 SwiftShader 软件渲染 |
| WebGL / Canvas | 使用原生能力、允许图像读取 | 关闭 WebGL 或阻止 Canvas 图像读取 |

随机音频标签来自随程序提供的公开型号目录，不表示物理设备直通。图形后端选择实际渲染路径，是否可用取决于 Debian 的驱动和显示服务；软件渲染可正常工作，硬件加速须由实际观测确认。关闭 WebGL 或 Canvas 读取会影响使用相应能力的网站。

## 保存与恢复

预览和编辑不创建虚拟磁盘。开始安装时，完整配置写入当前 profile 的 `guest-profile.json`；取消和续装、停止和重启、组件更新复用这份记录。安装开始后不能用不同创建配置覆盖已有账户和磁盘；若要使用另一组配置，应新建独立环境。

已有环境没有该文件时继续使用原账户、主目录和机器身份。配置损坏会明确报错，应保留原记录并从备份恢复。软件只替换自身受控模板中的账户与设备参数，项目路径、用户命令和附件名称按原值传递。

## 主动设备检测

在“网络与隔离检查 → 设备配置与渲染检测”点击“检测浏览器”或“检测 Claude Desktop”；Desktop 工具栏也提供“检测环境”。检测不要求开放外网。

- 系统观测读取客机主机名、工作账户、主目录及音频名称，并与已保存的创建配置比较。
- 浏览器检查在本地诊断文档中读取 UA 与 Client Hints、显示尺寸、实际渲染器，执行 Canvas 已知颜色回读及 WebGL 着色器、像素检查。浏览器身份跟随实际安装版本。
- 软件回退、字段不一致和缺失证据分别显示为需关注、未通过和未观测。没有音频标签权限时显示未观测。
- Claude Desktop 显示实际进程状态和版本；其内部渲染器缺少受支持的本地自检接口时显示未观测。

检测不会读取登录资料、设备序列号或申请麦克风权限。结果用于定位配置与渲染问题，不作为物理设备证明。
